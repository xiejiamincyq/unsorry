On Windows, every writer that materialises repo text artifacts now emits LF-only bytes. Python's text mode translates `\n` to `os.linesep` unless the writer passes `newline="\n"`, so on Windows the agent loop's extracted Lean module was written CRLF and no longer byte-matched the provider's fenced output (`swarm/agent.sh --self-test` failed `test_provider_text_module_extraction`), and an AISP goal-record rewrite churned every line of the record. Fixed at the three `swarm/agent.sh` py_helper sites and at every production writer of `.lean`/`.aisp`/`lean-toolchain`/`lakefile.toml`/`.patch` artifacts: `tools/seedkit`, `tools/sourcing` (`gen_triples`, `check_triviality`), `tools/intake` (`import_benchmark`, `remigrate_benchmark_subs`, `verifier_context`), `tools/archive/apply`, `tools/repo/relabel_attribution`, `tools/gate_a/check_statement_binding` and `tools/upstream/packet`. The seedkit and OpenAI-provider writers also relied on the platform locale encoding, which on a non-UTF-8 Windows codepage would raise `UnicodeEncodeError` on the AISP/Lean unicode they write; they now open explicitly as UTF-8. `tools/tests/test_windows_lf_artifacts.py` asserts the raw bytes carry no CR, so the regression is caught on Windows (POSIX passes trivially).
