`tools/dispatch/fair_order.py` now exits cleanly when the dispatch loop closes its output pipe early on Windows. The consumer (`dispatch_queue`) stops reading at its dispatch limit or on a submission-governor pause, which POSIX reports as `BrokenPipeError` (EPIPE) — already handled — but Windows reports the same condition as `OSError: [Errno 22] Invalid argument`, from both the buffered write and the interpreter's shutdown flush, so a traceback leaked into `run.sh`'s logs even though the dispatch succeeded (`swarm/agent.sh --self-test` failed `test_fair_dispatch_order_survives_early_reader_close`). The handler now catches `OSError`, swallows only a closed-pipe write (`BrokenPipeError` or EPIPE/EINVAL, so a genuine I/O error such as ENOSPC on a redirected stdout still surfaces), and wraps the devnull `dup2` so the cleanup path can never raise. POSIX behaviour is unchanged.
